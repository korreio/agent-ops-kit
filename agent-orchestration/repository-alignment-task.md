# Optional repository alignment task

Give a coordinator this task only for an explicitly named disposable or owner-authorized repository.
This is an adoption checklist, not authority to install global files or change another repository.

1. Read that repository's contract and current task. Identify who owns Git, tests and any hardware.
2. Read the supplied toolkit's `standing-orders.md`, `roster.md` and `orchestration-reference.md`.
   Resolve them from the toolkit location supplied by the owner, or a fully resolved installed
   loader link. If the location is missing, report it; do not search private trees.
3. Compare the existing instructions by role. Point at shared rules only where the owner wants
   them. Keep stricter local constraints and avoid duplicate policy authorities.
4. For optional memory relocation, stop writers first and use an explicit external private store.
   The repository's existing notes may be elsewhere; never merge, overwrite or delete them.
5. Record the proposed local edits, assumptions, effects and rollback in that repository's normal
   task record. Review the plan under its own contract before changing code or rule text.
6. Make authorized edits, run owning checks, obtain independent review and verify claims before
   fixes. Report missing proof and exact touched paths. Workers never mutate Git.

Use this when several repositories need consistent role language. Omit it when their existing
contracts already suffice. Adapt the comparison to their actual policies; no global installation,
synchronization, authentication change or repository enrollment follows from this document.
